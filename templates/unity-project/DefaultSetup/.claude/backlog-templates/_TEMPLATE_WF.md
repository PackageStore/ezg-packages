# WF Task Template — Workflow-Backed

Use for: a task whose implementation is **already specified deterministically by a `/new-*` workflow** in `.claude/commands/` (scaffold a new feature / package / skill / enemy-skill / UI / class). The workflow IS the plan — so `/planning-task` does NOT spawn the `task-planner` subagent for these. It only captures the workflow reference, the args, and any custom delta the workflow does not cover.

**Important — tier is orthogonal to WF:**
The filename still carries the real execution tier (`<timestamp>-<TIER>-<slug>.md`, usually `M`, or `L` if cross-cutting). That tier governs **review rigor** in `run-backlog` (which quality gates run). The WF marker only governs that `run-backlog` **loads the workflow first** instead of implementing free-form. A hybrid task (scaffold + extra custom logic) is "tier M, backed by workflow" — see `_TEMPLATE_M.md` / `_TEMPLATE_L.md`, which also accept the `**Backed by workflow:**` field.

Filename: `backlog/todo/NNN-TIER-short-slug.md`
