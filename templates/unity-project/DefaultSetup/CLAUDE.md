# CLAUDE.md

Chỉ dẫn **dùng chung** cho mọi project sinh từ EZG Unity game template. Claude Code nạp file này — cùng
`CLAUDE_PROJECT.md` mà nó import ở cuối — vào mọi phiên, kể cả subagent.

> **⛔ Project KHÔNG được sửa file này — chỉ sửa `CLAUDE_PROJECT.md`.**
> - `CLAUDE.md` thuộc template EZG: cập nhật từ Feature Hub (item `Config/CLAUDE.md`), `agents-update.sh`
>   hay chạy lại builder đều **ghi đè** nó — sửa tại chỗ sẽ mất ở lần cập nhật sau.
> - `CLAUDE_PROJECT.md` (root repo) thuộc project: tên game, gameplay bucket, scene, hệ thống / package /
>   quy ước / gotcha riêng. Commit cùng repo game; **không bao giờ** đẩy lên server dùng chung (monorepo
>   `ezg-packages`, Feature Hub, `defaultsetup.tgz`).
> - Dev hay agent muốn thêm/sửa chỉ dẫn cho Claude — kể cả khi được bảo "sửa CLAUDE.md" — thì sửa
>   `CLAUDE_PROJECT.md`. Phần dùng chung chỉ sửa ở `templates/unity-project/DefaultSetup/CLAUDE.md` trong
>   monorepo `ezg-packages` rồi publish (skill `publish-ai-features`).
> - Hai file mâu thuẫn → `CLAUDE_PROJECT.md` thắng.
> - Thiếu `CLAUDE_PROJECT.md` → chạy bootstrap (§0), nó tạo file từ khung `.claude/docs/CLAUDE_PROJECT.template.md`.
>   `CLAUDE.md` vừa bị ghi đè lên một bản cũ có nội dung riêng → lấy lại phần đó từ git
>   (`git log -p -- CLAUDE.md`) và chuyển sang `CLAUDE_PROJECT.md`.

## §0 — Bootstrap

Ba thứ agent system cần đều KHÔNG nằm trong git nên không thể ship kèm template: link view `.agents/`
(symlink/junction trỏ về `.claude/`), backlog (nằm trong `.git/backlog/`, không track được theo thiết
kế), và UI kit (trích từ prefab template của **chính project này** + mang hash của chúng, nên kit của
project khác là vô dụng). Chúng được tạo bằng bootstrap thay vì copy từ tarball.

**Sinh project bằng `build_unity_template` thì bootstrap đã chạy sẵn** — build script gọi nó ngay sau
khi copy `.claude/`, và điền luôn `projectName`/`solutionFile`/`gitConfigPrefix` trong
`.claude/project-profile.json`. Không cần làm gì thêm trước khi giao việc đầu tiên.

Chạy tay khi **clone** repo này về máy khác, hoặc để sửa một checkout hỏng nửa vời (ai đó xoá
`.agents/`, hoặc `.agents/` biến thành thư mục thật):

```bash
bash .claude/scripts/bootstrap.sh                                          # macOS / Linux
```
```powershell
powershell -ExecutionPolicy Bypass -File .claude/scripts/bootstrap.ps1     # Windows
```

Script này idempotent — chạy lại luôn an toàn. Nó tạo link view, `git init` nếu repo chưa có,
`backlog-ops.py init`, sinh UI kit nếu project chưa có, rồi tạo `.claude/docs/ArtStyle.md` và
`CLAUDE_PROJECT.md` từ khung nếu thiếu (không bao giờ ghi đè bản đã có). Chi tiết + việc còn phải làm tay (tinh
chỉnh `.claude/project-profile.json` cho khớp layout/threat surface, tạo remote nếu muốn push):
[.claude/docs/GETTING-STARTED.md](.claude/docs/GETTING-STARTED.md).

**Sau bootstrap: chạy `/setup-project`.** Mở project trong Unity rồi gõ `/setup-project` — skill mở cửa sổ
`Ezg > EzgKit` (package `com.ezg.ezgkit` ≥ 1.0): menu trái là các mục setup kèm trạng thái, form bên phải để
điền (tên dự án + bundle id, Google Sheet marketing + AppSecrets, ads & privacy, danh sách gói IAP, ArtStyle,
link localize; nhóm "Nâng cao": Firebase, nhà phát hành, social). Phần cần AI (soạn `ArtStyle.md` từ art
của game) skill tự làm khi dev bấm "Nhờ Claude". Xem [.claude/skills/setup-project/SKILL.md](.claude/skills/setup-project/SKILL.md).

**Chưa có `origin` là trạng thái hợp lệ.** `/run-backlog` tự dò remote và bỏ qua mọi lệnh network khi
không có — task vẫn implement, vẫn qua gate, vẫn commit, chỉ không push.

## Project Overview

This project is built on the EZG Unity mobile **game template** (Android/iOS). The template ships the
shared plumbing every project on this base needs — UI framework, two-tier data layer, resource/reward
economy, shop & IAP, analytics, localization, AssetBundle delivery, account sync — and **no gameplay**:
each project adds its own gameplay buckets on top. What this particular game is (name, genre, core
loop, gameplay buckets, scenes, extra systems) lives in `CLAUDE_PROJECT.md`, imported at the end of
this file.

Primary working directory: `Assets/_Project/`.

> **Where does new code go?** Domain buckets + per-feature layout + file-type→location table: see [.claude/rules/project-structure.md](.claude/rules/project-structure.md). Read it before creating any new file.

## Architecture

### Two-Tier Data System

**Runtime config** (read-only game data, CSV-sourced ScriptableObjects):
- Loaded via `DataManager.<CollectionName>` — e.g. `DataManager.GeneralConfig`, `DataManager.CoinPack`,
  `DataManager.UnlockFeature`
- Accessors are generated into `Features/_Shared/GameData/DataManager.Generated.cs`; the CSV→asset name
  map lives in `Features/_Shared/GameData/CsvAssetDir.cs`. Both are regenerated by the
  `com.ezg.csv-reader` import tool — do not hand-edit.
- CSV sources live in per-feature `CsvConfig/` folders (e.g. `Features/System/GeneralConfig/CsvConfig/`);
  the generated ScriptableObjects live in per-feature `Resources/` folders.
- There is no `DataManager.GetConfig<T>()` — only the generated properties (backed by `DataManager.Get<T>()`).

Collections the template ships (a project adds its own — `DataManager.Generated.cs` is the full list):
`UIDontDestroy`, `CoinPack`, `DailyDealsPack_1`, `GemPack`,
`RemoveAdsPack`, `ChangeName`, `DefaultResource`, `GeneralConfig`, `RatingConfig`, `ResourceExchange`,
`UnlockFeature`, `DynamicMoneyBarConfig`.

`DataManager` also exposes non-CSV assets loaded from `Resources`: `GeneralAssets`, `SoundConfig`,
`ShopNavigateConfig`, `UserAvatars`, `UserFrame`.

**Player data** (persisted, JSON in PlayerPrefs):
- Accessed via `PlayerDataManager.<Module>` — modules the template ships: `Account`, `Campaign`, `LoginActivity`,
  `Settings`, `PlayerResource`, `UnlockFeature`, `PlayerRating`, `PlayerShop`
- Each module extends `DataPlayerBase` / `DataPlayerBaseGeneric<T>` and is resolved at runtime via
  `DataPlayer.GetModule<T>()` (cached by `PlayerDataManager` — feature code should not call it directly)
- Defaults belong in the module's `SetupDefaultData()` override
- Save: `PlayerDataManager.<Module>.Save()`; never call `Save()` from an `Update` loop

### UI Feature System

All screens extend `FeatureBaseController`. Register the screen in the `GameEnums.Features` enum
(`Features/_Shared/Config/GameEnums.cs`) — the numeric values are serialized into prefabs, so add new
entries with unused numbers instead of renumbering existing ones. Open a screen via:
```csharp
UIManager.Instance.Show(GameEnums.Features.MyFeature, data: someData).Forget();
```

`UIManager` is a `Singleton<UIManager>` (`com.ezg.singleton`). Never use `gameObject.SetActive()` on a
feature screen — go through `UIManager`.

Six UI layers (lowest to highest), `UIManager.UIGroupName`:
`Main_Container → Modal_Container → CurrencyBar_Container → Overlay_Container → Tutorial_Container → Toast_Container`

A screen entry may carry `[BundleName("features__x")]` so `UIManager` loads its prefab from the matching
AssetBundle (see `Features/_Shared/AssetBundles/AssetBundleName.cs`).

### Event Bus

Uses TigerForge `EventManager` (static, string-keyed):
```csharp
EventManager.EmitEvent(EventName.SomeName);
EventManager.EmitEventData(EventName.SomeName, data: myData);
EventManager.StartListening(EventName.SomeName, handler);
EventManager.StopListening(EventName.SomeName, handler);
```

`EventName` is one `partial class` assembled from many files. Shared/system constants live in
`Features/_Shared/Systems/SystemEventName.cs` + `EventNameCompat.cs`; every feature adds its own
partial in `Features/{Domain}/{Feature}/Scripts/Data/{X}EventName.cs` (older features keep theirs in
`Scripts/Controller/`) instead of growing the shared file. There is no `Scripts/Events/` folder.

### Async

Use **UniTask** (Cysharp) throughout — never raw coroutines for new code:
```csharp
async UniTask DoSomethingAsync() { ... }
someAsyncTask.Forget(); // fire-and-forget
```

### Resource & Reward System

- Currencies: `EnumBase.MoneyTypes` (`Gold`, `Diamonds`, `Energy`, plus `Ads` / `Cash` pseudo-types).
  Resource categories: `EnumBase.ResourceTypes` (static `const int` class, not an enum).
- Balances live on `PlayerResource` (`PlayerDataManager.PlayerResource`) — `IsEnough`, `AddCurrency`,
  `RemoveCurrency`, `SetCurrency`.
- Granting rewards goes through `RewardsService` (`ReceiveReward` / `ReceiveRewards`, plus
  `CompileRewards`, `GenerateReward`, `ShowToast`, `Tracking`).
- Spending goes through `PurchaseManager`: `PurchaseOffline(...)` for soft-currency/ad costs,
  `PurchaseOnline(productId, ...)` for IAP. Project-specific side effects are injected via
  `PurchaseManager.Hooks` (`IPurchaseHooks`, default `TemplatePurchaseHooks`).

### Domain Buckets

The template ships these buckets under `Assets/_Project/Features/` (the project's own additions are
listed in `CLAUDE_PROJECT.md`):

| Bucket | Contents |
|--------|----------|
| `_Shared` | cross-cutting frameworks only (UI, GameData, Purchase, Networking, Analytics, Systems…) |
| `Meta` | `HomeScene` |
| `Monetization` | `Shop` (Store + RemoveAds) |
| `Onboarding` | `SplashScene`, `SelectLanguage` |
| `Social` | `Account`, `AvatarSelect`, `ChangeName`, `GiftCode` |
| `System` | `Admin`, `DefaultResource`, `GameCheat`, `GeneralConfig`, `OverviewCanvas`, `Rating`, `RequireInternet`, `ResourceExchange`, `RewardPopup`, `SaveFound`, `Settings`, `Tooltip`, `UnlockFeature` |

**The template ships no gameplay bucket.** Each project creates its own (e.g. `Features/Gameplay/`,
`Features/Combat/`…), records it in `CLAUDE_PROJECT.md`, and mirrors the standard feature layout
(`Scripts/Controller` = controller + static Service, `Scripts/Data` = player data + CSV model/collection
+ EventName, plus `CsvConfig/`, `Resources/`, `Visuals/` — those two are the only `Scripts/` sub-folders).
Never put single-feature code in `_Shared/`.

Scenes the template ships: `Assets/_Project/Scenes/SplashScene.unity`, `HomeScene.unity`, `BattleScene.unity`
(empty placeholder for the game scene).

## Branches

- `main` — production
- `develop` — nhánh tích hợp **theo quy ước, không được sinh sẵn**: project mới chỉ có nhánh mặc định của `git init`. Base branch của agent = nhánh đang mở lúc chạy loop; giá trị fallback là `defaultBaseBranch` trong `.claude/project-profile.json` (mặc định `main`).
- `agent/dev-<base>` — automated work branch, **chỉ dùng ở mode `worktree`**; cắt từ nhánh đang đứng lúc chạy loop, merge nhánh đó vào mỗi lần chạy, push (nếu có remote), **không** tạo PR. Ở mode `current` (mặc định) agent commit thẳng lên nhánh đang mở, không tạo nhánh nào.
- Cửa sổ `/fix-bug --watch` **không có nhánh riêng**: chạy watch ở nhánh nào thì sửa bug + push lên đúng
  nhánh đó (trước mỗi bug merge `origin/<nhánh>` vào), loop không bao giờ tự dừng. Mở bằng `/fix-bug --watch`
  trong một pane riêng hoặc `python3 .claude/scripts/bughub-watch.py start`. Muốn quay lại nhánh bot riêng
  (vd `AutoFixBug`, kèm worktree / merge ngược) thì khai `bugHub.watch.branch` trong `.claude/project-profile.json`.
- `IOS/AutoBuild` / `Android/AutoBuild` — nhánh build CI của module [`ezg-autobuild`](.claude/skills/auto-build-setup/SKILL.md) (tên mặc định; project đổi được lúc cài). Chỉ chứa scaffold `AutoBuild/` + `.gitlab-ci.yml` shim, cài/upgrade bằng `/auto-build-setup`. Chiều đồng bộ **một hướng**: nhánh Release → nhánh build (CI tự merge mỗi lần build) — **đừng bao giờ merge/push nhánh build ngược về Release**.

## Autonomous Backlog System

Tài liệu đầy đủ — các command `/planning-task` · `/planning-system` · `/add-to-backlog` ·
`/run-backlog` · `/ui-mockup`, roster subagent + model, hai mode `current`/`worktree`, loop + self-heal,
lease/claim/resume, preflight, lệnh `backlog-ops.py`, branch model của agent — nằm ở
[.claude/docs/backlog-system.md](.claude/docs/backlog-system.md). File đó **không** được nạp sẵn (để
khỏi tốn token ở mọi phiên và mọi subagent): đọc nó khi lên task, promote, chạy hay chẩn đoán loop, hoặc
sửa script backlog.
`/run-backlog` và các skill planning tự mang đủ quy trình của mình.

Invariant — áp cho MỌI phiên, kể cả việc làm tay:
- Backlog nằm ngoài worktree, ở `$(git rev-parse --git-common-dir)/backlog` (tức `.git/backlog`) —
  bookkeeping riêng từng dev: **không bao giờ** `git add` / `git mv` / commit file trong đó.
- Mọi chuyển trạng thái của task trong queue (todo / in-progress / done) và mọi sửa `BACKLOG.md` chỉ đi qua
  `python3 .claude/scripts/backlog-ops.py` (`lint`, `pick`, `start`, `done`, `promote`, …) — không hand-edit index.
- Trước và sau khi sửa script backlog (`backlog-ops.py`, `backlog-preflight.*`, loop controller,
  `run-backlog-refs.py`) hay skill `run-backlog`: chạy `python3 -m unittest discover -s .claude/scripts/tests`.
- `.claude/` là nguồn chuẩn; `.agents/` chỉ là link view trỏ về nó — chỉ sửa trong `.claude/`.

## Coding Notes

- **Vietnamese comments** are common and intentional — leave them in place; write new comments in Vietnamese.
- **Odin Inspector** attributes (`[TabGroup]`, `[SerializeField]`, `[ShowIf]`) are used throughout MonoBehaviours.
- **Editor tools** under `Assets/_Project/Editor/` are `#if UNITY_EDITOR` only.
- **Không reference game khác** — không tên game/studio bên thứ ba, không "giống game X", không ảnh/video
  game khác trong code, comment, asset, GDD, TechSpec, task, mockup. Chi tiết + ngoại lệ:
  [.claude/rules/no-external-game-refs.md](.claude/rules/no-external-game-refs.md).
- **Generated files** — `DataManager.Generated.cs`, `CsvAssetDir.cs`, `AssetBundleName.cs` are produced by
  tooling. Edit the source (CSV file / bundle config) and regenerate instead of hand-editing.
- **Template placeholders** — identity trong `ProjectSettings.asset` chưa điền: `applicationIdentifier` rỗng,
  `productName: Unity Game Template`, `companyName: DefaultCompany`. Store links, backend URLs và mọi per-app secret
  nằm trong `AppSecretsConfig`. Điền hết khi project thật được sinh ra — `/validate-release` chặn bundle id rỗng
  (blocker) và cảnh báo productName còn placeholder (warn).
